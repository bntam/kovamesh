Quickstart

90 seconds from install to your first verified signal. The CLI is open source (MIT) at github.com/bntam/kovamesh-verify.

1. Install the CLI

Requires Python 3.9 or newer. Use pipx for an isolated install (recommended), or plain pip:

pipx install kovamesh-verify
# or
pip install kovamesh-verify

kovamesh-verify --version
# kovamesh-verify 0.1.0

From source: git clone https://github.com/bntam/kovamesh-verify.git, then pip install -e . in the repo root.

2. Write a spec — kovamesh.yaml

One file describes what “working” means for your app. Checks run against a real running build, not against the source text:

name: my-app-smoke
base_url: http://localhost:3000
timeout_seconds: 10
checks:
  - name: app boots
    type: http
    path: /health
    expect_status: 200
  - name: login works
    type: http
    path: /api/auth/login
    method: POST
    body: {"email": "smoke@example.com", "password": "smoke-only"}
    expect_status: 200
    expect_json: {"ok": true}
  - name: no 500s in logs
    type: log
    pattern: " 500 "
    expect_absent: true

Check types: http (status, JSON body, response time), build (a shell command must exit 0), log (a pattern must be present or absent). See the repo README.md and examples/ for the full reference.

3. Run it

# start your app first, then:
kovamesh-verify run --spec kovamesh.yaml

# against a different base URL:
kovamesh-verify run --spec kovamesh.yaml --base-url https://staging.example.com

# machine-readable verdict:
kovamesh-verify run --spec kovamesh.yaml --json verdict.json

A passing run prints VERDICT: PASS and exits 0. A failing run prints the exact failing check, the response it got, and exits 1 — so CI can block the merge.

4. Run it in GitHub Actions

Add this job to .github/workflows/verify.yml. It installs the CLI, starts your app, and runs the spec on every pull request:

name: Verify PR at runtime
on:
  pull_request:
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install kovamesh-verify
      - run: npm ci && npm run build
      - run: npm start & sleep 5
      - run: kovamesh-verify run --spec kovamesh.yaml

The workflow in the kovamesh-verify repo itself (.github/workflows/ci.yml) runs the CLI’s own unit tests on every push — the same pattern, applied to itself.

Exit codes

Exit codeMeaningWhat to do
0All checks passedMerge with confidence; the verdict is in the evidence bundle.
1One or more checks failedRead the failing check’s output — it names the exact step and response.
2Spec or usage errorCheck the YAML (unknown check type, bad URL, missing file) and re-run.

FAQ

Does the CLI send my code anywhere?

No. kovamesh-verify runs entirely on your machine or in your CI runner. It only makes HTTP requests to the base_url you specify. The hosted KovaMesh loop (Startup / Enterprise) is a separate service and only receives the evidence bundle you choose to post.

Can I use it without Docker?

Yes. The CLI itself needs no Docker — it checks whatever app you have running. Docker is how the hosted loop isolates each PR run in a fresh sandbox; locally, you start the app however you normally do.

What if a check is flaky?

Don’t re-run the whole suite blind. Run kovamesh-verify triage (hosted) or check the 30-day history in the verdict: if the same check failed without a reproducing commit, quarantine it, file the evidence, and keep shipping. That’s the workflow in the CI triage demo.
